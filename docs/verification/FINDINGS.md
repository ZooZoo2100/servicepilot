## Additional finding during fixes

**F11 — high, observability isolation.** The new provider instrumentation initially used shared mutable `lastCall` state. A concurrent-request regression reproduced one conversation carrying the other request's ID/output in memory. This was introduced and caught in this verification phase, not a historical first-build bug. `evidence/provider-concurrency-before.txt` preserves the failure. Provider observations are now local to the request and retrieved through a conversation-keyed WeakMap; the output used for workflow decisions was never shared. No real provider call was made.

## Completed isolated exploratory baseline

`evidence/adversarial-isolated-before.json` contains **18/29 passing**, with 11 real failing cases. It uses the original production build on port 3200 with an in-memory database and the documented conversation-rate override. All 29 cases have requests, responses and tool traces. No unexpected successful booking mutation occurred in this campaign. The rate-limit parser failure from port 3000 remains a separate finding.

## Root-cause fixes applied

- **F01/F02:** introduce an explicit clarification state and conservative request constraints. Competing dates/vehicles cannot fall back to first availability or an arbitrary account vehicle. Unresolved corrections clear stale date/time/vehicle fields; reference-only replies preserve the pending operation. Three repeated recognized ambiguity attempts escalate. These are deliberately conservative checks, not complete language understanding.
- **F03/F04:** recognize negated mutations as withdrawal and keep cancellation/modification intent when the customer supplies only a reference. No confirmation semantics were relaxed.
- **F05:** safety is a response obligation carried independently of the handoff side effect. The fallback retains the driving warning and urgent priority. Tool summaries are bounded to their schema length while the handoff retains the longer conversation context.
- **F06/F07:** strict planner schema, calendar/time validation, owned-vehicle validation before context merge, and independent escalation ownership checks. Extra model properties cannot silently disappear into a seemingly valid plan.
- **F08:** explicit configuration preflight, a shared run-wide paid-call cap, forced Anthropic classification output, provider usage/diagnostics, partial-run metadata and failure triage. No paid run was attempted.
- **F09:** JSON rate-limit messages at the server and safe client fallback for non-JSON proxy responses. Drafts remain intact.
- **F10:** in simulation, an explicit booking request retains booking intent when a customer also asserts a price; the price still comes exclusively from the catalogue.
- **F11:** request-local observations and a conversation-scoped lookup eliminate mutable cross-request diagnostic state. The failing concurrent regression and fix are preserved separately.

These fixes do not prove the absence of other failures. In particular, the simulation still uses limited patterns, and a schema-valid live model can misinterpret intent or suggest a wrong-but-available date. Independent confirmation and business rules limit effects, but do not prove semantic correctness.

**F12 — medium, evaluation/observability defect introduced during this phase.** A turn rejected by the model budget inherited the previous turn’s provider observation, potentially double-counting tokens. `evidence/provider-budget-observation-before.txt` records the failed assertion. The failure path now attaches an observation only if a new request observation was created during that turn. This changes neither billing nor operational state; it makes the reported evidence accurate.

## Pre-credential hardening

**F13 — high, credential hygiene.** New offline regressions demonstrated that a credential accidentally included in customer text persisted in conversation data, and provider input/output lacked explicit redaction. Provider debug logging was not explicitly disabled. No real credential was involved or leaked; tests used dummy sentinels. `evidence/credential-safety-before.txt` preserves the genuine failure. The fix centralizes server-side redaction at inputs and JSON sinks, scrubs provider metadata/output, disables SDK logs, pins official provider endpoints, ignores live reports pending review, and adds a repository/index/browser-bundle credential check.

**F14 — medium, cost control.** Direct adapter calls could submit oversized context despite the HTTP message cap. The same before-evidence shows an oversized request reached mocked transport. A 32,000-byte serialized context ceiling now rejects it before network dispatch. Shared paid-run budget and tool ceilings already existed; additional concurrent/failure tests verify that failed requests consume the budget and cannot race past it. First-run configuration is now ten calls.

The initial secret-check script falsely flagged blank example values because its whitespace regex crossed line boundaries; the complete first check records this local tooling defect. It now uses the dotenv parser. No historical score was rewritten.
